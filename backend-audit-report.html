Venue owner email exposed to any visitor Unfixed
lib/actions/venues.ts:375
getVenueById() includes the venue owner's email: true in the public response. Any visitor can see the owner's email address by browsing any venue. Fix: Remove email: true from the owner columns — only include id and name. (1 line, 30 seconds)

deleteUserAccount is a no-op stub Unfixed
lib/actions/users.ts:420
The function checks authentication, then returns { success: true, message: "Account deletion initiated" } without actually deleting or anonymizing anything. Fix: Either implement soft-delete (anonymize name/email, clear sessions) or remove the feature entirely. For a demo, simply removing the function is cleanest.
HIGH — Tutor reading the code will see it's a stub
PII still logged to console (user email) Unfixed
auth.ts:17, auth.ts:21, app/api/uploadthing/core.ts:35

MEDIUM — PII in logs if ever deployed
Drizzle config reads wrong env file Unfixed
drizzle.config.ts
drizzle.config.ts loads .env.local but the project only has .env. Running drizzle-kit generate or push will fail to find DATABASE_URL. Fix: Change config({ path: ".env.local" }) to config({ path: ".env" }). (1 line, 30 seconds)
MEDIUM — DB migrations will fail
any types with eslint-disable in server actions Unfixed
lib/actions/venues.ts, lib/actions/reports.ts
venues.ts and reports.ts have /* eslint-disable @typescript-eslint/no-explicit-any */ and cast update data to any. A tutor looking at the code will notice. Fix: Replace any with proper partial types (e.g., Partial<typeof venues.$inferInsert>). (~5 minutes)
MEDIUM — Visible in code, shows carelessness

No one will brute-force a demo app. Adding Upstash/rate limiting adds complexity with zero demo benefit.

Fine for demo-sized data. Only matters with hundreds of venues.
